# 需求与成功标准

运营人员输入主题、预算、截止时间；系统使用合成素材和工具价格/耗时表，输出任务计划、步骤依赖、实际步骤状态、工具结果、实际费用、预计费用及保存的方案或未完成原因。

| 编号 | 必验 | 判定 |
| --- | --- | --- |
| A01 | 正常完成 | 依赖满足，预算/时间合规，保存方案有真实 ID |
| A02 | 缺预算或截止 | 明确缺失字段，不调用付费工具，不虚构默认预算/期限 |
| A03 | 工具失败 | 失败步骤明确 failed，保留此前成功结果，模型选择重试、替代或停止 |
| A04 | 预算超限 | 预算 10、premium 估算 12，模型切换 basic 估算 8；无可行方案时返回缺口 |
| A05 | 重复执行 | 同一请求/资料版本不重复收费、不重复生成成功步骤、仅一份保存方案 |
| A06 | 加分续跑 | 失败状态跨进程保存；再次执行同一请求只补未成功步骤 |

业务边界：预算是模拟单位，最多两位小数，内部整数分计算；截止时间必须带时区。基线价格：检索 2、premium 脚本 8/basic 脚本 4、保存 2，估算免费，所以总额 12/8。失败尝试不收费但计模拟耗时 1 分钟；失败一次后可成功的故障次数持久化，跨进程重启不重新注入。已成功且被放弃的产物仍计费用，不能通过换计划抹掉成本。

模拟耗时并非真实工具延迟；真实模型耗时计入真实时钟。当前进度时间取 max(真实当前时间, 首次创建时间+累计模拟耗时)，不重复累加二者。每次付费动作前重新检查预计完成时间与费用，恰好等于上限允许。已经过期不能保存新方案；既有完成方案重复读取是历史结果。

需求、预算、截止或目录版本改变必须使用新 request_id；补齐缺失信息也用新编号，避免覆盖历史请求。不支持真实采购、发布、跨用户授权或无界后台调度。
