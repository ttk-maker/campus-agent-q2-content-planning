内容活动方案使用手册

1. 打开正确的入口

在仓库目录运行 py -3.10 -m src.web，访问 http://127.0.0.1:8767/。

localhost:11434/v1 是模型 API 前缀，浏览器直接打开可能返回 404。它不是此工作台网页。GitHub 托管代码，也不等于在线运行服务。

2. 第一次规划

  1. 选择“预算 10 · 超限后重规划”，检查主题、预算和截止时间。时间采用浏览器本地时区，发送时转换为带时区的时间戳。
  2. 先选“离线演练”，点击“开始规划”。高级方案估算 12，基础方案估算 8；Agent 会根据工具结果选择可行方案。
  3. 查看实际费用、步骤状态及保存状态。只有“已保存”且有方案 ID 才代表保存成功。输出是合成活动方案，不会真实发布或消费。
  4. 展开“动作与工具观察”查看参数、观察、下一步和简要依据；点击“导出运行记录”保存输入、输出和 Trace。

3. 使用真实模型

安装并启动 Ollama，运行 ollama pull qwen2.5:7b-instruct。网页服务默认连接本机该模型，不需要 API Key。选择“真实模型”后执行。CPU 推理可能需要数分钟；每次模型请求最多等待 90 秒，每次规划默认最多 16 步。

离线演练使用固定策略，只证明流程和工程守卫。真实模式由模型逐步决策，可能选择不同路径、重试工具或明确停止。

4. 故障、续跑与重复执行

  1. 选“基础脚本失败一次 · 续跑”：离线模式首轮会检索成功、脚本失败，费用为 2。
  2. 点击结果区“续跑 / 重复执行原请求”。系统从数据库读取成功检索，只补跑脚本和保存，总费用为 8。真实模型也可能在同一轮重试成功。
  3. 已完成后再点击此按钮，返回同一方案 ID，不新增费用或方案。
  4. 修改主题、预算、截止时间或工具配置后，点击“生成新 ID”再运行。同 ID 改输入会返回 idempotency_conflict，防止复用不匹配结果。

失败次数、成功结果和账本保存在 runtime/workbench.db。进程重启后可提交相同原始请求续跑。浏览器保存最近一次请求；完整 Trace 需及时导出，服务内运行记录只保留最近 100 次，重启后清空。

5. 如何理解未完成

  • 待补信息：预算或截止时间缺失，不默认补齐。填写后生成新 ID。
  • 无可行方案：查看预算缺口和超时分钟，决定是否调整要求并新建请求。
  • 执行失败：失败步骤不记成功，已有成果保留；确认模型或工具恢复后续跑。
  • 达到步数上限：明确未完成，可查看 Trace 后继续执行原请求。若方案已实际保存但模型未结束，以单独显示的保存状态为准。
  • 页面连接失败：确认启动命令仍在运行，刷新页面；不要把模型 API 地址当成网页。

6. 费用与时间口径

检索 2 + 高级脚本 8 / 基础脚本 4 + 保存 2，总计 12 / 8。估算免费但耗时 1 分钟；失败不收费但耗时 1 分钟。已成功但后来放弃的脚本仍计费，不会因更换方案抹除。

检索耗时 3 分钟；高级 / 基础脚本 20 / 8 分钟；保存 2 分钟。工具检查采用“真实当前时间”和“创建时间 + 累计模拟耗时”的较晚者，再加剩余耗时。截止时间是硬约束。若首次估算或失败增加耗时，原本可行的计划可能变为不可行。
